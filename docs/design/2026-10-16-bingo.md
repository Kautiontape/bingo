# bingo.kautiontape.com: design

Date: 2026-10-16
Status: agreed, not yet built

A people-watching bingo game at `bingo.kautiontape.com`. Grown from the Rebecca Black Fit Bingo artifact
(https://claude.ai/artifact/HR4CcC1N1YxMxWM1abpSKU): same card, marking and win logic, plus a default
people-watching board, custom boards, and shared boards that several people play live.

## Decisions and why

| Decision | Choice | Why |
|---|---|---|
| What a share link joins | The creator picks per board: **Everyone gets a card** (shared list, own card each) or **One shared card** (everyone marks the same card) | Both are wanted. "Everyone gets a card" also answers the open question of sharing only the configuration: the link carries the list, never anyone's marks. |
| Names | Auto fun name on join (e.g. "Suspicious Pigeon", "Man With Baguette"), tap to rename, remembered in the browser | No prompt between scanning a QR code and playing. |
| Who controls a shared board | Only the creator, via a creator key kept in their browser | Joiners never manage setup. They play, share, or make their own. A stray tap can't wipe everyone's game. Cost: control doesn't follow the creator to another device. |
| Backend | Small Node service on ktn (Hono + better-sqlite3), live updates over Server-Sent Events | Same deploy path as yeetbin, data stays on ktn, no third-party account. Cloudflare Durable Objects and hosted realtime (Firebase, Supabase, PartyKit) were considered and rejected as new platforms for a toy. |
| Frontend | Vanilla JS modules, no framework | The artifact is already vanilla and small. |
| Expiry | Boards deleted after 90 days with no activity | Long enough to create a board well before an event. |
| Port | `127.0.0.1:8116` | 8100–8115 are taken on ktn (8110 is Actual). 8116 is unused and unreferenced. |
| Repo | `Kautiontape/bingo`, public | Same as yeetbin. |

## 1. How it plays

### Boards

- A first visit deals a 5×5 card, free center, from about 100 generic people-watching items. This private board
  lives in localStorage only and never touches the server. Default title: "People Watching Bingo".
- Sharing a private board turns it into a shared board at `bingo.kautiontape.com/b/<id>`. The person who shares it
  is its creator. A private board is shared as "Everyone gets a card".
- The root URL opens the last board you had open (private or shared).

Starter items are things you could spot in any public space: short (about four words or fewer), observable at a
glance, light cheek is fine ("Picking nose", "Baby in stroller", "Drinking coffee", "Talking on phone"). They
live in `phrases.js`, along with the word lists for fun names.

### The ✦ menu

A glowing button at the top of the board opens it. What it holds depends on whose board it is:

| Your own board (private, or a shared board you created) | Someone else's shared board |
|---|---|
| Share & QR | Share & QR |
| New round (re-deal and clear marks) | Make my own |
| Clear marks | Create custom board |
| Edit squares (fix text in place) | |
| Edit board (create form, prefilled) | |
| Create custom board | |

On a shared board, the creator's actions apply to everyone:

- **New round.** In "One shared card" mode, deals a new shared card. In "Everyone gets a card" mode, deals every
  player a new card. Marks clear in both modes.
- **Clear marks.** Clears the shared card, or every player's marks.
- **Edit squares.** On the shared card, edits the cell. In "Everyone gets a card" mode, renames that item in the
  list and on every card that holds it, and keeps the marks. This is for fixing a typo mid-game.
- **Edit board.** Saving a title-only change keeps the round. Changing the items, size or free square starts a
  new round. Mode is fixed once a board is created.

Joiners can't shuffle or clear their own card. To undo a wrong mark, they tap the square again.

### Create custom board

A form with:

- Title
- Items, one per line, with a live count ("38 items · 24 per card")
- Size: 3×3, 4×4 or 5×5
- Free center square, with editable text (odd sizes only)
- Mode toggle: **Everyone gets a card** / **One shared card**

Submitting creates the shared board on the server, deals the card, and opens the share popup at once. If the
server can't be reached, the board is kept as a private board and the popup shows Retry.

### Share popup

Opens right after creating a board, and from the menu at any time. It holds the link, a QR code, a Copy button,
and the phone's native share sheet (`navigator.share`) where available.

### Make my own

Copies a shared board's title, items and settings into a new private board in your browser and deals you a card.
Nothing is shared until you tap Share.

### Joining and playing together

- Joining assigns a fun name and color with no prompt. Tap your name to rename.
- **Everyone gets a card:** you're dealt your own card. A players strip under the card shows each player's
  progress (marks, how many away from a bingo, BINGO).
- **One shared card:** anyone can mark or unmark any square. Each marked square shows a small dot in the color of
  whoever marked it last. The player who completes a line is credited with the bingo.
- In both modes, a toast announces bingos: "Maya got BINGO!"
- The creator is a player too.

### Bingo

- Confetti keeps raining as long as you have a bingo, until you dismiss it. With `prefers-reduced-motion`, you
  get one short burst instead.
- The buttons at the bottom glow. On your own board: **New round** and **Create a board**. On someone else's:
  **Make my own** and **Create a board**.
- The win rules are the artifact's: any row, column or diagonal. Several lines show "BINGO ×n"; marking every
  square shows "BLACKOUT".

## 2. Architecture

### Frontend (`public/`)

| Module | Job |
|---|---|
| `card.js` | Pure logic: deal a card from items, list winning lines, count bingos. **Imported by the server too**, so client and server can't disagree about a bingo. |
| `phrases.js` | The ~100 starter items and the fun-name word lists. |
| `store.js` | localStorage: private boards, creator keys and player tokens per board id, your name, last board opened. Every access is wrapped in try/catch, since storage can be missing. |
| `sync.js` | API calls, the live-update stream, a queue of marks that retries while offline. |
| `ui/` | Menu, create form, share popup (QR code), players strip, toasts, confetti. |

All user text is rendered with `textContent`, never `innerHTML`.

### Server (`server/`)

| Module | Job |
|---|---|
| `db.js` | SQLite schema and setup (`/data/bingo.db`). |
| `boards.js` | Game rules over the database: create, join, mark, rename, new round, clear, edit, edit square, expire. No HTTP. |
| `routes.js` | HTTP layer (Hono): validation, auth, rate limits. Serves `public/`. |
| `events.js` | One live channel per board: fan-out of events to that board's open streams. |

### Data model

**boards**

- `id`: 10-character random id, unguessable
- `creator_key_hash`: SHA-256 of a random 128-bit creator key
- `mode`: `cards` or `shared`
- `title`, `items` (JSON array), `size`, `free`, `free_text`
- `round`: increments on each new round
- `shared_card` (`shared` mode only): JSON, with cell text plus the player who marked each cell
- `created_at`, `last_active`

**players**

- `board_id`, `id` (public, shown to others)
- `token_hash`: SHA-256 of a random 128-bit private token
- `name`, `color`
- `card` (`cards` mode only), `marks` (bitmask; 25 bits covers 5×5), `round`
- `updated_at`

The server deals all cards, at join and at each new round. That is what lets a creator's New round re-deal
everyone at once.

### API

Writes carry the player token, or the creator key for creator actions, in a header.

| Method and path | Who | Does |
|---|---|---|
| `POST /api/boards` | anyone | Create a board. Returns `{id, creatorKey}`, and the creator is joined as the first player. |
| `GET /api/boards/:id` | anyone | Snapshot: settings, players, your card if your token is sent. |
| `POST /api/boards/:id/join` | anyone | Returns `{playerId, token}`. The server picks the fun name and color. |
| `POST /api/boards/:id/mark` | player | `{cell, on}`. An explicit on/off rather than a toggle, so two people tapping one square at once don't cancel out. |
| `PATCH /api/boards/:id/me` | player | Rename. |
| `POST /api/boards/:id/round` | creator | New round. |
| `POST /api/boards/:id/clear` | creator | Clear marks. |
| `PUT /api/boards/:id` | creator | Edit board settings, or rename one item (`{from, to}`). |
| `GET /api/boards/:id/events` | anyone | Server-Sent Events stream. |
| `GET /b/:id` | anyone | The page, with the board title in `<title>` and the Open Graph tags (HTML-escaped), so links preview as "Airport Bingo". |

### Live updates

- One `EventSource` per open shared board.
- Every connect starts with a full snapshot, so a dropped connection reconnects and is caught up. Missed events
  don't matter.
- Events: `snapshot`, `player` (join, rename, progress), `mark`, `bingo`, `round`, `board` (edit).
- A heartbeat comment goes out every 25 seconds so Cloudflare (about 100 seconds) and nginx keep the stream open.

### Failure handling

- Marks show instantly. If a send fails, it's queued and retried on reconnect.
- If the server is down, private boards still work fully. Creating a custom board falls back to a private board
  with Retry in the share popup.
- An unknown or expired link shows "This board's gone" with a fresh people-watching card.
- A lost player token (cleared storage, new device) means rejoining as a new player. At the 50-player cap, players
  idle for more than 24 hours are dropped to make room.

### Limits and abuse

- Up to 200 items of 80 characters each. Titles up to 60 characters, names up to 30.
- Up to 50 players per board.
- Rate limits keyed on the client IP, which nginx passes from Cloudflare's `CF-Connecting-IP`: 20 board creations
  per hour per IP, and a burst cap on marks per token.
- An hourly sweep deletes boards whose `last_active` is more than 90 days old.

### Tests

- Unit tests (`node --test`) for `card.js` (dealing, lines, bingo counts, free square, blackout) and `boards.js`
  against an in-memory SQLite database (modes, rounds, creator-only actions, item rename, expiry, player cap).
  They gate the image build in CI.
- One Playwright run, done locally before phase 2 ships: create a board, open it in a second browser context,
  mark squares in both, check the players strip and the bingo toast.

## 3. Deploy

The same pattern as yeetbin (container) and twilight-aid (nginx conf kept in the repo).

- **Dockerfile:** multi-stage `node:24-alpine`. Production dependencies only in the final image. `PORT=3000`,
  `DATABASE_URL=/data/bingo.db`.
- **docker-compose.yml:** `ghcr.io/kautiontape/bingo:latest`, `127.0.0.1:8116:3000`, volume `bingo_data:/data`,
  `restart: always`.
- **`.github/workflows/build-publish.yml`:** on push to `main`, run the unit tests, then build and push the image to
  GHCR (`latest` plus sha tags).
- **`.github/workflows/deploy.yml`:** after a successful build, on the `[self-hosted, ktn]` runner, run
  `cd /opt/services/bingo && git pull && docker compose pull && docker compose up -d && docker image prune -f`.
- **`deploy/bingo.kautiontape.com.conf`** (the source of truth; copy it to ktn):
  - Port 80 redirects to HTTPS. Port 443 uses `include snippets/ssl-kautiontape.conf`.
  - `proxy_pass http://127.0.0.1:8116`, with `X-Real-IP $http_cf_connecting_ip`.
  - `location ~ ^/api/boards/[^/]+/events$`: `proxy_buffering off`, `proxy_cache off`, `proxy_http_version 1.1`,
    `proxy_set_header Connection ""`, `proxy_read_timeout 1h`.
  - The server sends `Cache-Control: no-cache` for the HTML page and long-lived caching for static assets.
- **DNS and TLS:** already done. `*.kautiontape.com` resolves through Cloudflare, and
  `/etc/ssl/cloudflare/kautiontape.com.pem` covers `*.kautiontape.com`.

One-time steps on ktn (Shawn):

1. `git clone https://github.com/Kautiontape/bingo.git /opt/services/bingo`
2. Copy `deploy/bingo.kautiontape.com.conf` to `/etc/nginx/sites-available/`, symlink it into `sites-enabled`, then
   `sudo nginx -t && sudo systemctl reload nginx`.
3. `cd /opt/services/bingo && docker compose up -d` (or trigger the deploy workflow).

## Build order

Each phase ships on its own.

1. **The game.** Project scaffold, `card.js` + tests, the ~100 phrases, the people-watching default board, the ✦
   menu, the create form (it makes a private board until phase 2; the mode toggle waits too), Edit squares,
   confetti, the glowing bottom buttons, private boards in localStorage. The container serves the static files; no API yet. Dockerfile, compose, CI, nginx
   conf, first deploy.
2. **Sharing.** Server modules, API, live updates, join with fun names, players strip, toasts, both modes,
   creator controls, Make my own, the share popup with link and Copy, expiry, limits. Playwright run.
3. **Polish.** QR code, native share sheet, Open Graph tags on `/b/:id`, a link on the kautiontape.com landing
   page.
